Turn the DeepSeek web chat into a local API.

An Android bridge that drives the real DeepSeek (and Arena) chat UI inside a hidden WebView and exposes it as an OpenAI-compatible endpoint on your device. No API key. No SDK. No external proxy.

Quick start → Architecture

How it works

A local server in front of a real browser session.

The app runs an HTTP server inside itself. Any OpenAI-compatible client posts a normal chat-completion request; the bridge types it into the live web UI, waits for the reply to stream in, scrapes the answer, filters UI noise, and returns it as standard JSON. 

client  ──POST──▶  LocalApiServer  ──▶  WebView (chat.deepseek.com)  ──▶  model
                        ◀────────────── scraped reply ◀────────────────┘

Anti-detection hardening

Engineered to look like a person, not a scraper.

  • ✓
    Randomised request delay

    Configurable range (default 3–6 s). Never a fixed interval — a machine-precise rhythm is the easiest thing to fingerprint.

  • ✓
    Session warmup

    The first N requests run slower, the way a human explores a new session before settling into a pace.

  • ✓
    Burst protection

    Consecutive fast requests receive an escalating, capped penalty instead of triggering a block.

  • ✓
    Desktop user-agent

    Mobile WebView signature is masked with a desktop Chrome identity.

  • ✓
    Human-like typing

    Value-set plus real input events, never a raw clipboard paste.

  • ✓
    No hard request caps

    Throttling only. The bridge never returns a 429 that would kill a live working session.

Quick start

Two steps to a live endpoint.

bash
# 1 · install the APK and log in to DeepSeek in the WebView

# 2 · point any OpenAI-compatible client at the local server
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer <local-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-webview","messages":[{"role":"user","content":"hi"}]}'
web api/deepseek/bridge.properties
# hot config — edit on disk, next request uses it
requestDelayMinMs=3000
requestDelayMaxMs=6000
sessionWarmupDelayMs=7000
sessionWarmupCount=10
